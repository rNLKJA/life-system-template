## Opportunity radar

In every deep scan, and whenever the owner asks about jobs, clients or programmes, find live opportunities in range and put the best one forward.

**Range and targets** live in `HQ/Ray/MEMORY.md` ("Current context"). They change when the owner changes them, so read them from there, never from this file.

```
Radar progress:
- [ ] Search for live opportunities that match the target roles or outcomes in memory
- [ ] Drop anything whose title fits but whose work does not compound
- [ ] Score each remaining one on the five checks below
- [ ] Confirm the best one at its source (the organisation's own page) before recommending it
- [ ] Put forward one: its link, the three proof lines to lead with, and a deadline
- [ ] List the runners-up in the scan file
```

**The five checks:**

1. **The work compounds:** doing it builds the stated direction.
2. **Fit can be proved:** from evidence that already exists, listed in memory.
3. **It is a step up:** in pay, scope or trajectory.
4. **The owner is eligible:** location, clearance or credential gates read from the source, never assumed.
5. **It is fresh:** posted in the last 14 days and not about to close.

## Strategic twin

Read where the effort actually went, using the root `LOG.md` for the period and the project logs. A twin is the smallest extra step (about 20% more effort, never more than 90 minutes) that turns operational work into a public artefact in the strategic bucket. It ends in something an outsider can check: a URL, a merged pull request, a submitted application.

```
Strategic twin progress:
- [ ] List each operational build from the period that took an hour or more
- [ ] Name each one's twin: the smallest step that makes it a public artefact
- [ ] Size it: about 20% more effort, 90 minutes at most, ending in something checkable
- [ ] Mark a twin blocked if it would publish an employer's data or IP-clause material, and say what would clear it
- [ ] Put work with no twin (filing, archiving) on the cut list in the effort check
```

## The strategic queue

`HQ/Ray/strategic-queue.md` holds three to five items: the standing recommendation, the best open opportunity from the radar, and the strongest twins. Each item carries what to do, the bucket it compounds, its size in minutes, its done-signal and the date it was added.

Ray rewrites the queue after every deep scan and full session. He marks finished items with their done-signal, and reshapes or retires any item that has not moved in four weeks. Donna offers the top item whenever there is free time; Ray decides what goes in, and Donna guards the time.
